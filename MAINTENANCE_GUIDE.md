# 🩺 Здоровье • Руководство по обслуживанию

## 1. Где что лежит

```
Health care/
├── 01_… 06_…                       документы (только на ПК)
├── medical_database_2024_2026.json исходная база (архив, только на ПК)
├── .private/pii_terms.txt          список персональных данных для проверки (только на ПК)
└── app/                            git-репозиторий приложения (публикуется)
```

Всё, что вне папки `app/`, физически не может попасть в репозиторий.

## 2. Три уровня защиты от утечки

1. **`.gitignore`** — PDF, JPG, JSON-данные, `.env`, резервные копии игнорируются git.
2. **Проверка перед коммитом** (`.githooks/pre-commit`) — GitHub Desktop не даст сделать коммит,
   если среди файлов есть документ, открытый JSON, файл `.enc` без шифрования, ключ API
   или персональные данные из `.private/pii_terms.txt`.
3. **Проверка на GitHub** перед публикацией сайта — повторяет проверку для репозитория и готовой сборки.

Если коммит заблокирован — в окне GitHub Desktop будет список файлов и причин. Уберите эти файлы из коммита.

## 3. Первая публикация (один раз)

1. GitHub Desktop → **File → Add local repository…** → выбрать папку `Health care\app`.
2. **Publish repository** → имя `Health-Dashboard` → **снять** галочку *Keep this code private*
   (GitHub Pages бесплатно работает только для публичных репозиториев) → Publish.
3. На сайте GitHub: репозиторий → **Settings → Pages → Build and deployment → Source: GitHub Actions**.
4. Через 1–2 минуты сайт доступен: `https://<аккаунт>.github.io/Health-Dashboard/`.

## 4. Обычное обновление

1. Внести изменения (на следующих этапах — `update.bat`, затем `publish.bat`).
2. GitHub Desktop → описание → **Commit to main** → **Push origin**.
3. Ход публикации — вкладка **Actions** репозитория.

## 5. Список персональных данных `.private/pii_terms.txt`

По одной строке: ФИО (латиницей и кириллицей), адрес, телефон, e-mail, номера документов.
Строки короче 4 символов игнорируются, `#` — комментарий. Файл никогда не публикуется.
